## Finding T2.9: A multi-document YAML stream silently compiles only the first document

Location: `src/TruthWeaver.Yaml/YamlTreeParser.cs:57` (PLAUSIBLE, low)

Parse uses stream.Documents[0] and ignores the rest. The JSON surface rejects trailing content as malformed, so the two tree formats disagree on a stream with more than one document.

### Failure scenario

`const: true\n---\nconst: false\n` compiles to True with no diagnostic. A reviewer who reads the whole file may take the second document as the rule.

### Expected behavior

Report MalformedTree when the stream holds more than one document.

## Agent Brief

**Category:** bug
**Summary:** A YAML input containing more than one document (separated by `---`) silently compiles only the first document, with no diagnostic — disagreeing with the JSON surface, which rejects trailing content as malformed.

**Current behavior:** YAML parsing takes only the first document from the stream and ignores the rest. A rule author or reviewer who writes (or receives) a multi-document YAML file sees no error, and the compiled rule reflects only the first document — silently discarding whatever follows.

**Desired behavior:** A YAML stream containing more than one document reports the malformed-tree diagnostic, the same as a structurally invalid document, instead of silently compiling the first and discarding the rest.

**Key interfaces:**
- `YamlTreeParser.Parse`.

**Acceptance criteria:**
- [x] A YAML stream with two or more documents reports the malformed-tree diagnostic instead of compiling.
- [x] A single-document YAML stream is unaffected.
- [x] The validation list in `CLAUDE.md` passes.

## Resolution (2026-11-01)

Reproduced: `CompileYaml("const: true\n---\nconst: false\n")` compiled to `True` with no diagnostic. `YamlTreeParser.Parse(string)` now reports `MalformedTree` (TRE0014) at `$` when the stream holds more than one document, with the span on the root node of the second document and the document count in the message. This also covers `YamlRuleDefinitions`, which reads through the same method. One document with explicit `---` and `...` markers still compiles. `YamlDataSource` is unchanged: its XML docs state that it reads only the first document of a data file. Tests: `YamlTreeTests.CompileYaml_MoreThanOneDocument_ReportsMalformedTree_Test` (two and three documents) and `CompileYaml_OneDocumentWithMarkers_Compiles_Test`. Pages updated: `docs/rule-formats.md`, `docs/strong-k3/specification/diagnostics.md`.
