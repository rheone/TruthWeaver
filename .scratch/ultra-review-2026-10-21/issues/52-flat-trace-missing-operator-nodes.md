## Agent Brief

**Category:** bug
**Summary:** The flat trace (`Decision.Trace.Entries`, populated when `IncludeTrace` is set) only logs terms, constants, quantifiers, and skipped nodes — never a visited operator node (AND/OR/NOT/XOR/threshold/If) — contradicting `CONTEXT.md`'s "one entry per node visited or skipped" and `EvaluationOptions.IncludeTrace`'s "every term and operator."

**Current behavior:** The evaluator's flat-trace-entry call is made only for constants, terms, quantifiers, and skipped nodes. A visited NOT/AND/OR/XOR/threshold/If node only contributes to the tree-shaped `TraceNode`, never to the flat `Entries` list. An existing pinned test asserts this leaves-only shape for `a AND b` (entries `["a", "b"]`, no `"AND"` entry).

**Desired behavior:** Every node the evaluator visits or skips — including operator nodes — contributes one entry to the flat trace, matching the documented contract. For `a AND b` with `IncludeTrace`, the flat trace includes an entry for the `AND` node as well as for `a` and `b`.

**Key interfaces:**
- The evaluator's flat-trace-entry call needs to run for operator nodes (AND/OR/NOT/XOR/threshold/If/COALESCE/etc.), not just constants/terms/quantifiers/skips.
