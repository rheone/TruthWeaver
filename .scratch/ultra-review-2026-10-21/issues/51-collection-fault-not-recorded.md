## Agent Brief

**Category:** bug
**Summary:** A collection-level fault (throwing selector, element-limit exceeded) adds directly to the fault list, bypassing the shared fault-recording path that also writes the evaluation log and increments the fault metric — so collection faults are invisible to logging and metrics even though a normal predicate fault isn't.

**Current behavior:** A throwing collection selector or an exceeded element limit adds its fault directly, duplicating the fault-budget check inline rather than going through the central fault-recording path. That path is what also writes the log entry and increments the fault counter; bypassing it means collection faults never appear in either.

**Desired behavior:** A collection-level fault goes through the same central fault-recording path a predicate fault already uses, so it's logged and counted identically — no behavior change to `Decision.Faults` itself, which already carries the fault correctly.

**Key interfaces:**
- Collection binding's fault-recording calls (throwing selector, element-limit exceeded) should route through the evaluator's central fault-recording method instead of adding to the fault list directly.
