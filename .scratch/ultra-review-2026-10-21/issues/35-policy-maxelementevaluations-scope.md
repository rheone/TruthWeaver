## Finding F9.5: MaxElementEvaluations is a whole-set bound but is documented as per evaluation

Location: `src/TruthWeaver.Policies/PolicySet{TContext}.cs:101` (PLAUSIBLE, medium)

state.ElementEvaluations lives in the shared EvaluationState, so the 10,000 default bound (EvaluationOptions.cs:24-31, 'in one evaluation') is spent across all rules of the set. docs/policies.md and ADR-0015 say only the fault budget becomes a whole-set concept. When the bound is hit, the set aborts and every later rule is Unknown. Because of the first finding, the limit fault is also dropped.

### Failure scenario

Three policies each contain `FORALL(l IN lines, ...)` over a 4,000-line order. Each rule alone is under the limit. In the set, the third quantifier exceeds 10,000, the evaluation aborts, the third and later policies are Unknown, and the outcome is Indeterminate with no fault in PolicyDecision.Decision.Faults.

### Expected behavior

docs/policies.md says the element bound is shared across the set, or the set accounts for the element bound per rule.

Decision: document `MaxElementEvaluations` as shared across a `PolicySet`, matching the fault budget's already-documented whole-set behavior, rather than changing the code to give each rule its own allowance (which would raise a set's total resource cost per rule sharing the state). ## Agent Brief

**Category:** bug (documentation)
**Summary:** `MaxElementEvaluations` is spent across an entire `PolicySet` (all rules share one `EvaluationState`'s running count), but `docs/policies.md` and ADR-0015 describe it as a per-evaluation bound — only the fault budget is currently documented as a whole-set concept.

**Current behavior:** `EvaluationState.ElementEvaluations` is shared by every rule in a `PolicySet`. `EvaluationOptions`'s documentation describes the 10,000 default as bounding "one evaluation." When several quantifier-heavy policies share a set, the combined element count can exceed the bound partway through, aborting the remaining rules to `Unknown` — correct behavior, but undocumented at the set level.

**Desired behavior:** `docs/policies.md` and ADR-0015 state that `MaxElementEvaluations`, like the fault budget, becomes a whole-set bound when rules share an `EvaluationState` — a host that needs more headroom for a set with many quantifier-heavy policies raises `MaxElementEvaluations` on the shared options, the same way it would for a single rule today.
