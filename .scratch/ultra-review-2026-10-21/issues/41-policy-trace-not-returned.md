## Finding F9.6: IncludeTrace collects a trace that PolicyDecision never returns

Location: `src/TruthWeaver.Policies/PolicySet{TContext}.cs:189` (PLAUSIBLE, low)

The shared state collects trace entries when options.IncludeTrace is true. Each rule's Decision copies the full trace so far, so the cost grows quadratically with the number of rules. Build then creates a new Decision with no trace, so the caller gets nothing for this cost. No doc says what IncludeTrace does for a set.

### Failure scenario

A caller passes EvaluationOptions(IncludeTrace: true) to a 50-policy set to debug a denial. Every rule allocates a copy of the growing trace, and PolicyDecision.Decision.Trace is still null.

### Expected behavior

Either the set's decision carries the trace (or each policy's trace), or the docs say that IncludeTrace has no effect on a set and the set does not collect one.

## Agent Brief

**Category:** enhancement
**Summary:** `PolicySet` evaluation with `IncludeTrace` already collects a growing trace in its shared state at real cost, but `PolicyDecision` is built with no `Trace` argument, so the caller gets nothing back for that cost.

**Current behavior:** When `EvaluationOptions.IncludeTrace` is set, the shared `EvaluationState` collects trace entries as each rule in the set runs; each rule's own per-rule `Decision` copies the full trace collected so far (a real, growing allocation cost). The set's final `PolicyDecision` is built without passing any of that collected trace through, so `PolicyDecision.Decision.Trace` is always `null` regardless of `IncludeTrace`.

**Desired behavior:** With `IncludeTrace` set, a caller evaluating a `PolicySet` gets back a trace they can actually read — either the deciding rule's own trace surfaced on `PolicyDecision.Decision`, each rule's individual outcome carrying its own already-collected trace, or an equivalent combined form. Pick whichever shape best fits how `PolicyDecision`/`PolicyRuleOutcome` (or their equivalents) are already structured; the goal is that `IncludeTrace` on a `PolicySet` stops being a no-op.

**Key interfaces:**
- `PolicySet<TContext>.Build` (where the final `Decision` is currently constructed with no `Trace`).
- Whatever per-rule outcome type the set already exposes, if trace is better attached there instead of (or in addition to) the top-level `Decision`.

**Acceptance criteria:**
- [ ] Evaluating a `PolicySet` with `IncludeTrace: true` returns a non-null, non-empty trace the caller can actually inspect, reflecting what happened during the set's evaluation.
- [ ] Evaluating with `IncludeTrace: false` (or omitted) behaves exactly as it does today (no trace collected, no change in cost).
- [ ] `docs/policies.md` documents the chosen shape.
- [ ] The validation list in `CLAUDE.md` passes.

**Out of scope:**
- Reducing the trace-collection cost itself (already paid regardless of this fix; a separate concern if it needs addressing).
