## Agent Brief

**Category:** bug
**Summary:** The predicate source generator doesn't detect a `[Predicate]` method with two parameters that differ only in case (C# allows it; the rule languages don't), so the collision surfaces as a runtime `ArgumentException` at host startup instead of a build-time diagnostic.

**Current behavior:** A `[Predicate]` method can declare parameters like `role` and `Role`, both case-sensitive-distinct in C# but colliding once case-insensitive argument names reach the registry. The generator emits both as arguments with no diagnostic; the build succeeds. `PredicateRegistryBuilder.RejectCaseVariantArguments` then throws when the generated `Register` call actually runs, contradicting the documented promise that every problem from this generator is a build error, never a run-time one.

**Desired behavior:** A `[Predicate]` method whose parameter names collide case-insensitively is a generator diagnostic at build time, and the generator emits no `Register` call for that method.

**Key interfaces:**
- The predicate source generator's method reader (the step that currently emits arguments with no case-collision check).
- A new generator diagnostic code, in the same family as its other `[Predicate]`-method diagnostics.

**Acceptance criteria:**
- [ ] A `[Predicate]` method with two parameters differing only in case produces a generator diagnostic and the build fails (or clearly flags it), rather than succeeding.
- [ ] No `Register` call is emitted for that method.
- [ ] A method with no case-colliding parameters is unaffected.
- [ ] The validation list in `CLAUDE.md` passes.

**Out of scope:**
- `PredicateRegistryBuilder.RejectCaseVariantArguments`'s existing run-time check (kept as a backstop, not removed).
