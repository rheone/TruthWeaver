## Agent Brief

**Category:** bug
**Summary:** YAML's duplicate-key rescan decides it's inside a predicate's `args` mapping by checking whether the current path ends in `.args`, which also matches a definition (or other node) literally named `args` — so a repeated key under that definition is mislabeled `DuplicateArgument` instead of the correct `MalformedTree`.

**Current behavior:** The rescan that distinguishes "a repeated key inside a predicate's `args` mapping" (reported as `DuplicateArgument`) from "a repeated key anywhere else" (reported as `MalformedTree`) checks only whether the enclosing path's text ends in `.args`. A definition named `args` (or a predicate argument named `args` whose value is itself a mapping) produces the same path suffix, so a repeated key there gets the wrong diagnostic — even though the document is correctly rejected either way.

**Desired behavior:** The rescan tracks that the enclosing frame is specifically a predicate node's `args` member, not just that the path text happens to end in `.args`, so a repeated key under an unrelated node named `args` gets `MalformedTree` like any other repeated key.

**Key interfaces:**
- `YamlTreeParser`'s duplicate-key rescan (`FindDuplicateArgument`).

**Acceptance criteria:**
- [ ] A repeated key under a definition named `args` reports `MalformedTree`, not `DuplicateArgument`.
- [ ] A repeated key inside an actual predicate's `args` mapping still reports `DuplicateArgument` (no regression).
