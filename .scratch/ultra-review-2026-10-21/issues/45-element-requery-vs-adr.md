## Finding F8.8: The element projector runs once per distinct query, not once per element as ADR-0010 states

Location: `src/TruthWeaver/Registry/LazyElementDataSource.cs:19` (PLAUSIBLE, low)

LazyElementDataSource calls projector(item) on every QueryAsync and ScopeAsync. The ADR-0010 amendment says 'the delegate runs at the first query of that element'. The evaluator memoizes per (scope, reference), so each distinct query of one element builds a new source.

### Failure scenario

elementSource = item => JsonDataSource.Create(JsonSerializer.SerializeToNode(item)), and a body with three different from(line, ...) references over 10,000 lines. The code serializes 30,000 times instead of 10,000. A projector with side effects or non-deterministic output gives different terms of one element different views of the element.

### Expected behavior

Cache the projected source (or the projection exception) in LazyElementDataSource after the first call.

not verified (medium or low)

## Finding F8.9: Outer data sources are queried again for each quantifier element, against ADR-0006 decision 11

Location: `src/TruthWeaver/Registry/CollectionBinding.cs:189` (PLAUSIBLE, low)

WithElementSource passes outer sources unchanged into each nested evaluator, but the answer memo key is (memoScope, reference) (Evaluator.cs:742), and memoScope differs per element. An outer from("cfg", "$.limit") inside a body is queried once per element. ADR-0006 decision 11 says each (source, query) pair is queried at most once within one evaluation.

### Failure scenario

FORALL(line IN lines, under(max: from("cfg", "$.limit"))) over 500 lines, with a live config source. That makes 500 backend calls. If the value changes during the evaluation, line 1 and line 400 are checked against different limits within one evaluation.

### Expected behavior

Memoize references to sources that the element binding does not shadow at the outer scope, or amend ADR-0006 decision 11 to state the per-element scope.

## Comments

Decision: fix the code for both findings, matching the already-documented ADR intent, rather than amending the ADRs to accept the current behavior. ADR-0006 decision 11's "at most once per evaluation" promise exists specifically for consistency — the failure scenario's own example (two elements checked against different config values within one evaluation, if a live source changes mid-run) is exactly the inconsistency the ADR was written to prevent, so loosening the ADR would be documenting away a real correctness property, not just a technicality.

## Agent Brief

**Category:** bug
**Summary:** Two related over-querying defects: a quantifier's element projector re-runs once per distinct query of an element instead of once per element (against ADR-0010's amendment), and an outer data source referenced inside a quantifier body is re-queried once per element instead of once per evaluation (against ADR-0006 decision 11).

**Current behavior:** `LazyElementDataSource` calls its projector function on every query of an element, not just the first — so three distinct `from(...)` references inside one quantifier body against one element project it three times. Separately, the answer memo for an outer-scope `from(...)` reference is keyed per-element (because the memo scope differs per element), so an outer source referenced inside a quantifier body is queried once per element instead of once for the whole evaluation — allowing a live/changing source to give different elements inconsistent answers within one evaluation.

**Desired behavior:** A quantifier element's projection runs at most once per element (cached after the first query, per ADR-0010's amendment). An outer-scope data-source reference inside a quantifier body is queried at most once for the whole evaluation (memoized across elements, per ADR-0006 decision 11), not once per element.

**Key interfaces:**
- `LazyElementDataSource`: cache the projected source (or the projection exception) after the first call for a given element.
- The quantifier element-binding's memo scope for an outer-scope reference needs to resolve to the outer evaluation's scope, not a fresh per-element scope, when the reference isn't shadowed by the element binding.

**Acceptance criteria:**
- [ ] A quantifier body with multiple distinct `from(...)` references over one element projects that element's source exactly once, not once per reference.
- [ ] An outer-scope `from(...)` reference inside a quantifier body is queried exactly once for the whole evaluation, not once per element.
- [ ] A reference to the element's own (shadowing) source is unaffected — still queried per the element-binding rules.
- [ ] The validation list in `CLAUDE.md` passes.

**Out of scope:**
- Amending ADR-0010 or ADR-0006 decision 11 to accept per-element re-querying — considered and explicitly not chosen.
