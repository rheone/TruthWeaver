## Finding L3.3: A note written on a `use` node is dropped when the use expands

Location: `src/TruthWeaver/Compilation/DefinitionExpander.cs:299` (PLAUSIBLE, medium)

ExpandUse returns ExpandNode(definition.Body, ...) and never carries the UseNode's own Note onto the expanded root (Carry is applied only to the body's nodes), so the note is lost before NoteCollector runs. rule-tree.schema.json lists `note` on useNode, rule-formats.md:209 says any JSON node can have one and rule-formats.md:16 promises `parse(print(x))` keeps the same notes; a use whose body root has no note of its own loses the annotation with no diagnostic.

### Failure scenario

JSON `{"definitions":{"adult":{"body":{"predicate":"isAdult"}}},"op":"use","name":"adult","note":"age gate"}` (or rule text `let adult = isAdult; /* age gate */ adult`) compiles, but CompiledRule.Notes is empty and PrintJson()/PrintRuleText() of the compiled rule no longer contain 'age gate'. The code side is wrong: the use's note should land on the expanded root (or the loss should be documented and the key rejected).

### Expected behavior

A note on a use node is kept on the node the use expands to (or joined with that node's own note), so CompiledRule.Notes and the printers preserve it.

## Agent Brief

**Category:** bug
**Summary:** A note written on a `use` node is dropped when the use expands, instead of being carried onto the expanded root, so it never reaches `CompiledRule.Notes` or a round-trip print.

**Current behavior:** Expanding a use returns the definition's body expansion directly; the use node's own note (if any) is discarded in that return, rather than being attached to the node the use expands to. A rule with a note on a `use` node compiles successfully but silently loses that note — it doesn't appear in `CompiledRule.Notes`, and printing the compiled rule back out doesn't contain it either.

**Desired behavior:** A note on a `use` node survives expansion by landing on the node the use expands to. If that node already carries its own note (from the definition body itself), join the two rather than dropping either.

**Key interfaces:**
- Use-node expansion must carry the use's own note onto the expanded result, the same way every other node kind's note is carried through expansion.

**Acceptance criteria:**
- [ ] A `use` node with a note, expanding to a body with no note of its own, keeps the note: it appears in `CompiledRule.Notes` and in a round-trip print.
- [ ] A `use` node with a note, expanding to a body whose root already has its own note, keeps both (joined), rather than dropping either.
- [ ] The validation list in `CLAUDE.md` passes.

**Out of scope:**
- Notes on any node other than `use` (already handled correctly).
