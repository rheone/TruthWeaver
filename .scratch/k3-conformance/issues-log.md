# k3-conformance: issues log

## Summary for review

Reconciled 2026-10-03 after the k3-followups tickets 01-19. The evidence is [research-findings.md](research-findings.md) (what was run and measured) and [spec-audit.md](spec-audit.md) (what the reference documents got wrong); the follow-up work is in [`.scratch/k3-followups/`](../k3-followups/spec.md). Every row below has a status in the last column:

- **Resolved**: fixed or closed, with the ticket named in the row.
- **Kept**: a decision is recorded and stands; reopen only if a consumer or use case appears.
- **Open**: needs the repo owner's confirmation. Nothing blocks the work; each has a working default.
- **Info**: recorded for information, no decision needed.

Open questions that need the repo owner's decision, row numbers referring to the table below:

1. **Syntax and spelling to confirm.**
   - Row 15: `COALESCE` chains, the `??` tree-style spelling and the canonical function-call form.
   - Row 18: ternary mixed with `AND`/`OR` is an error even where C precedence would resolve it; relax to "lowest precedence"?
   - Row 19: `If` operand-count errors use `MalformedTree`, and `If` has no symbolic/C-style tree spelling.
   - Row 27: the name and location of `RuleText.NormalizeWhitespace`, and whether prefix `!` should be spaced (`! a`).
2. **Predicate catalog.** Questions 2, 4, 7 and 8 in [`.scratch/predicate-catalog/k3-gap-list.md`](../predicate-catalog/k3-gap-list.md) (`NotX` shape, collection `In`/`NotIn`, bounds, selector shapes) are deferred and gate any implementation of the 49 missing inventory predicates. Questions 1, 3, 5 and 6 are resolved (k3-followups 10).

Resolved by the follow-ups since the last review: the collapse and project safety semantics (rows 21-23, 29-31; `Collapse` and `Project` are `Decision` methods and `Decision.Result` is always raw), the `If(Unknown, A, A)` semantics (row 17, pinned by an oracle test), the `NXOR` to `PARITY` rename (row 12), the shared arity code constant name `InfixArityViolation` (rows 7, 11, 35), `PrintRuleText` and the `Diagnostic.Path` syntax (rows 26, 37), the C-style spellings (rows 8, 10) and the environment rows (1-3).

Kept by decision, to revisit only on demand: rows 6, 9, 12-14, 20, 25, 28, 29, 31, 33, 34, 36, 38. Informational rows: 5, 16, 32, 39, 40.
