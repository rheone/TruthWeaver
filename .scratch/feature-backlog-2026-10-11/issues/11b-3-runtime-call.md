# 11b-3: Runtime call("x")

**Parent:** [11b](11b-rule-library.md)

**What to build:** `call("x")` and `call("x", hash: "...")` in rule text. The node stays in the tree and evaluates another compiled rule of the library at evaluation time. Its value is the call node's value. Its faults join the caller's fault list and count against the caller's fault budget. Its trace nests under the call node. Timeout and cancellation come from the caller's options. The compiler checks existence, pin and cycles with the expand references. If a reload later removes or changes the rule, the call node returns Unknown plus a Fault. Decide in this ticket how analysis (BDD, normal forms, rewrites) treats a call node: as an opaque term, unless the owner prefers otherwise; report the choice. ## Agent Brief

**Category:** enhancement
**Summary:** Add a runtime `call("x")` node that evaluates another compiled rule of the `RuleLibrary` at evaluation time.

**Current behavior:**
`RuleLibrary` exists and `rule("x")` expands a library rule inline at compile time (11b-2). No node type evaluates a library rule at run time. Authority: ADR-0019, decisions 7 and 9.

**Desired behavior:**
- Rule text accepts `call("x")` and `call("x", hash: "...")`. The node stays in the compiled tree.
- The value of the node is the value of the callee. The callee's faults join the caller's fault list and count against the caller's `FaultBudget`. The callee's trace nests under the call node. Timeout and cancellation come from the caller's `EvaluationOptions`.
- The compiler checks existence, the pin and cycles with the same checks as `rule("x")`. A cycle through `rule` and `call` together is one compile error that lists the path.
- If a reload later removes the callee, or changes it under a hash pin, the call node returns `Unknown` plus a `Fault`, and `Decision.IsSatisfied` is false (fail-closed). An unpinned call follows a reload and runs the new version (owner decision 2026-11-05).
- Analysis (BDD, normal forms, rewrites) treats a call node as an opaque term keyed by name and hash pin. Two calls with the same name and pin are the same atom. Analysis never looks inside the callee. The "no tautologies" documentation says a call is not an information-monotone claim.
- New diagnostic codes are never reused.

**Key interfaces:**
- The operator checklist in `CLAUDE.md` ("Adding or changing an operator"): parser, `RuleNodeCompiler`, `Evaluator`, `Analyzer`/`BddManager`, `NodeShape`, one `OperatorDefinitions` entry, printers.
- `RuleLibrary` and `CompilerOptions`: how the evaluator reaches the current library at run time. Follow ADR-0019; choose the mechanism and report it.
- JSON, YAML, `RuleBuilder` and `rule-tree.schema.json` stay with 11b-4.

**Acceptance criteria:**
- [x] A call returns the callee's value; its faults and trace appear in the caller's `Decision`
- [x] A removed callee, or a callee changed under a hash pin, returns `Unknown` plus a `Fault`, and `Decision.IsSatisfied` is false; an unpinned call follows a reload

- [x] Two calls with the same name and pin are one atom in analysis; the callee body is never inspected
- [x] Pages updated in the same change (rule text, diagnostics table, evaluation trace, glossary); `CHANGELOG.md` entry; doc-example and `K3ReferenceSyncChecker` tests pass
