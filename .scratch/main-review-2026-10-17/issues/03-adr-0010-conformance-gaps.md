## Answer

Investigated by reading the code the reviewer could not run against; no build or test was executed (reading
was sufficient to confirm or refute every item). Evidence is file:line against the current working tree.

| # | Item | Verdict | Evidence |
| --- | --- | --- | --- |
| 1 | `ToCnf`/`ToDnf` normalize only the outer tree, not the quantifier body | **CONFIRMED** | `src/TruthWeaver/Rewriting/NormalForms.cs:276-286` — `NnfBuilder.VisitCore`'s `QuantifierExpression` case only runs `this.Visit(q.Body, negate)` (NNF), never the CNF/DNF `Distribute` step. `Distribute` (`NormalForms.cs:60-71`) treats a `QuantifierExpression` as an opaque leaf (`[[node]]`) because it is neither `OrExpression` nor `AndExpression`, so it never recurses into `Body` to form clauses. Repro (in words): compile and `ToCnf()` `FORALL(x IN c, a OR (b AND NOT a))`; the printed body stays `a OR (b AND NOT a)` (already NNF) and is never rewritten to `(a OR b) AND (a OR NOT a)`, even though decision 9's table says "its body is put into normal form on its own." |
| 2 | No exhaustive truth-table oracle over collection sizes 0-4 plus `null` for quantifier rewrites | **CONFIRMED** | `tests/TruthWeaver.Tests/K3ConformanceTests.cs` is the project's existing oracle pattern (every `{True,False,Unknown}` assignment, arities up to `MaxArity = 4`) and has no `FORALL`/`EXISTS` entry. No test file matches an exhaustive collection-size-0-to-4-plus-null sweep for quantifiers (checked `QuantifierEvaluationTests.cs`, `QuantifierFormsTests.cs`, `QuantifierAnalysisRewritesCoverageTests.cs`, and a repo-wide search for "0 to 4" / exhaustive collection enumeration). The ADR's own text (decision 9, closing paragraph) requires this oracle for every rewrite that touches a quantified rule. |
| 3 | `RuleCoverageAccumulator` skips body terms and counts bodies per element instead of "reached in at least one element"; empty collection records nothing for the body | **CONFIRMED, but one sub-claim is not a gap** | Excluding body terms from the distinct-term list is **intended**, not a gap: `Flatten` (`src/TruthWeaver/Evaluation/RuleCoverageAccumulator.cs:262-269`, comment at 244-249) deliberately skips `RegisterTerm` `insideBody`, matching decision 8 verbatim ("the terms inside a body" are excluded from "the terms of a rule"). The real gaps: `PairElement` (`RuleCoverageAccumulator.cs:367-391`) increments `nodeCounts` once **per element** of every decision, not once per decision with a union outcome, so a body node's `EvaluatedCount`/`TrueCount`/etc. are element-occurrence counts, not "reached in at least one element" counts as decision 7 specifies. And for an empty collection, `traceNode.Children` is empty (`Pair`, `RuleCoverageAccumulator.cs:329-345`), so `PairElement` is never called and no body-subtree node gets any increment (not even `NotEvaluated`) for that decision — it is silently missing from the denominator instead of counted. |
| 4 | `Decided` stops at the body root | **CONFIRMED** | `PairElement` calls `ChangesResultBounded(i, other, elementValue, bodyIndex)` (`RuleCoverageAccumulator.cs:386`), and `ChangesResultBounded` (`RuleCoverageAccumulator.cs:477-506`) returns `true` as soon as the recomputation reaches `subtreeRoot` (the body root), without checking whether that change actually flips the quantifier's own AND/OR fold or the rule's final result. Every other node's `DecidedCount` means "changes the result of the rule" (`NodeCoverage.cs:14-17`); for a body node it silently means "changes the body's own result" instead. |
| 5 | `CheckValues` trusts `QuantifierExpression => true`, so a mismatched quantifier trace is never detected | **CONFIRMED** | `CheckValues`/`CheckBodyValues` (`RuleCoverageAccumulator.cs:394-438`) both have `QuantifierExpression => true` unconditionally. The in-code comment justifies this by analogy to a term's value being "not recomputable from a single operand value" — true for a term, but the quantifier's own fold **is** recomputable from the per-element body results that `Pair` already reads while walking `traceNode.Children` (`RuleCoverageAccumulator.cs:329-345`): an AND-fold for `ForAll`/OR-fold for `Exists` over those per-element results could be compared against the quantifier's own recorded value. No such comparison exists, so a decision whose recorded quantifier value doesn't actually follow from its own element trace passes silently, unlike every connective node (checked via `CombineAt`). |
| 6 | Body diagnostics may not use the body's own path | **NOT A GAP** | Checked every place a body's path is threaded: JSON/YAML (`src/TruthWeaver/Parsing/TreeFormatReader.cs:699`, `ReadQuantifier` passes `TreePath.Index(operandsPath, 0)` into `ReadNode` for the body), `RuleBuilder` (`src/TruthWeaver/Building/RuleBuilder.cs:1107-1110`, `QuantifierBuilder.CollectProblems` does the same), and the compiler (`src/TruthWeaver/Compilation/RuleNodeCompiler.cs`, every diagnostic uses `node.Path`/`PathOf`, and `BuildQuantifier` passes the already-pathed `node.Body` into `CollectionBinding.CompileBody`). All three correctly produce `$.operands[0]...`. Separately, the analyzer's tautology/contradiction diagnostics (`src/TruthWeaver/Analysis/Analyzer.cs:635,641`) never attach a `path` at all (always `SourceSpan.None`, no `path:` argument) for outer-rule or body findings alike — so there is no quantifier-specific regression there either; it is a pre-existing, uniform limitation unrelated to ADR-0010. |
| 7 | `CONTEXT.md` and the ADR-0005 connective list do not name `FORALL`/`EXISTS` | **NOT A GAP — already done** | `CONTEXT.md:201-218` has a dedicated "Quantifiers" section naming `FORALL`/`EXISTS`, collection binding and element context. `docs/adr/0005-strong-k3-language-surface.md:598-602`, decision 18, is amended in place: "...and, *amended 2026-10-16* (ADR-0010), the quantifiers `FORALL` and `EXISTS`." Both match the ADR's own "Consequences" commitment. |
| 8 | ADR-0010 is not amended with the diagnostic-code allocation or the chosen `elementSource` registration shape | **CONFIRMED** | The ADR's "Open questions" section still reads as unresolved (`docs/adr/0010-forall-exists-quantifiers.md`, "Open questions for the owner": "does not allocate `TRE` codes... the next free code is `TRE0042`" and "the exact registration shape... is **not fixed by this ADR**"), but the implementing code already decided both: `src/TruthWeaver/Diagnostics/DiagnosticCodes.cs:250,256,262` allocates `UnknownCollection = "TRE0042"`, `MaxQuantifierDepthExceeded = "TRE0043"`, `ShadowedVariable = "TRE0044"`; and `src/TruthWeaver/Registry/PredicateRegistryBuilder.cs:73-78` took the "additional delegate parameter on `AddCollection<TItem>`" option (`elementSource`), one of the three choices the ADR named but left open. The ADR was never amended in place to record either decision, despite its own text promising to do so once decided. |

### Proposed follow-up tickets

1. **ToCnf/ToDnf: normalize a quantifier's body into the requested normal form, not just NNF.** The body currently only gets NNF via `NnfBuilder`; it must also go through `Distribute`/`Assemble` for `Cnf`/`Dnf`, recursively, in the body's own scope. Status: ready (confirmed gap, scope is clear: `src/TruthWeaver/Rewriting/NormalForms.cs`).
2. **Add the quantifier exhaustive truth-table oracle (collection sizes 0-4 plus `null`, every element assignment).** Mirrors `K3ConformanceTests.cs`'s pattern for `FORALL`/`EXISTS` and every rewrite that touches a quantified rule, per decision 9's closing paragraph. Status: ready.
3. **`RuleCoverageAccumulator`: fold a quantifier body's per-element coverage into "reached in at least one element" with union outcomes, and record an empty collection's decisions instead of dropping them.** Status: needs-triage — the owner should confirm the exact counting semantics first (e.g., does "Evaluated" rise by 1 per decision when *any* element reached the node, and do `True`/`False`/`Unknown` become independent "at least one element had this value" flags, which can make more than one of the three true for one decision?) before `PairElement` is rewritten.
4. **`RuleCoverageAccumulator`: make `Decided` for a quantifier-body node propagate through the quantifier's fold to the rule root**, instead of stopping at the body root, so its contract matches `NodeCoverage.DecidedCount`'s documented "changes the result of the rule." Status: ready.
5. **`RuleCoverageAccumulator`: validate a quantifier's recorded value against the AND/OR fold of its own element trace** in `CheckValues`/`CheckBodyValues`, instead of trusting `QuantifierExpression => true` unconditionally, so a mismatched quantifier trace is caught like every other node. Status: ready.
6. **Amend ADR-0010's Open Questions with the diagnostic-code allocation (`TRE0042`-`TRE0044`) and the `elementSource`-delegate-parameter registration shape**, both already decided in code, per the ADR's own instruction to update itself in place. Status: ready (documentation-only).

No follow-up ticket is proposed for items 6 and 7: both are already satisfied by the current code and docs.
